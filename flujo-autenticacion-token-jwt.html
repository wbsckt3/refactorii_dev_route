2 ¿Qué es JWT (JSON Web Token)?

🔷 Estructura de un JWT:

Un JWT tiene 3 partes separadas por puntos (.)

JWT Token Structure
1️⃣ Header (Encabezado):

Contiene el algoritmo de encriptación y el tipo de token

JSON - Header
2️⃣ Payload (Carga útil):

Contiene los datos del usuario y metadatos (claims)

JSON - Payload
3️⃣ Signature (Firma):

Firma digital que garantiza que el token no ha sido modificado

Pseudocódigo - Signature
✅ Ventajas de JWT:
  • Stateless: No requiere almacenar sesiones en el servidor
  • Portable: Se puede enviar en URL, headers o body
  • Firmado: Garantiza integridad (no puede ser modificado)
  • Con expiración: Tiene fecha de caducidad automática

7 Flujo Completo con Validación por Token

🔑
1. Usuario hace Login con Google
Google autentica y devuelve datos del usuario
💾
2. Backend genera Token JWT
  • Backend recibe email del usuario
  • Genera token con jwt.sign()
  • Incluye email, _id, y fecha de expiración
  • Firma con clave secreta
📦
3. Frontend guarda Token
  • Token se guarda en localStorage
  • Token se incluye en URLs como query param
  • Token se puede enviar en cabecera Authorization
✅
4. Validación en Frontend
  • Verifica que existe token
  • Verifica que no esté expirado (decodifica JWT)
  • Si válido → muestra aplicación
  • Si inválido → muestra login
🌐
5. Petición API con Token
  • Frontend envía token en cabecera Authorization: Bearer <token>
  • Backend extrae token de la cabecera
  • Backend valida con jwt.verify()
  • Si válido → extrae email del token y procesa petición
  • Si inválido → devuelve error 401

8 Ventajas y Desventajas del Método con Token

✅ Ventajas:
  • Mayor seguridad: Token firmado, no puede falsificarse
  • Expiración automática: Tokens expiran sin intervención
  • Stateless: No requiere almacenar sesiones en servidor
  • Portable: Se puede enviar en URL, headers o body
  • Información incluida: Datos del usuario en el token
  • Mejor rendimiento: Menos consultas a BD
⚠️ Desventajas:
  • CORS más complejo: Requiere configurar 'Authorization'
  • Revocación difícil: No se puede invalidar fácilmente
  • Tamaño: Tokens pueden ser largos en URLs
  • Exposición: Token visible en URLs (logs, historial)
  • Configuración: Requiere manejo de clave secreta seguro

9 Recomendaciones de Implementación

🔒 Seguridad:
  • Usar process.env.JWT_SECRET para la clave secreta (nunca hardcodear)
  • Usar tiempos de expiración cortos (1 hora o menos)
  • Implementar refresh tokens para renovar sin re-login
  • Validar siempre el token en cada petición
📝 Mejores Prácticas:
  • Enviar token en cabecera Authorization (no en URL si es posible)
  • Usar HTTPS siempre para proteger tokens en tránsito
  • Implementar rate limiting por token
  • Loggear intentos de tokens inválidos para seguridad
⚠️ Consideraciones CORS:
  • Asegurar que Authorization esté en allowedHeaders
  • Configurar Access-Control-Allow-Credentials: true si usas cookies
  • Probar preflight requests (OPTIONS) funcionan correctamente
  • Considerar usar query params como fallback si CORS falla

10 Resumen

📋 Para implementar validación por Token necesitas:
  1. ✅ Instalar jsonwebtoken: npm install jsonwebtoken
  2. ✅ Crear endpoint para generar tokens después del login
  3. ✅ Modificar endpoints para validar token con jwt.verify()
  4. ✅ Agregar 'Authorization' a allowedHeaders en CORS
  5. ✅ Modificar frontend para enviar token en cabecera Authorization
  6. ✅ Manejar errores de token expirado o inválido
💡 Decisión:

Validación por Email: Más simple, menos segura, funciona sin problemas CORS.
Validación por Token: Más segura, requiere configuración CORS, mejor para producción.
