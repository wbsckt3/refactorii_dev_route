2 ¿Qué es JWT (JSON Web Token)?

🔷 Estructura de un JWT:

Un JWT tiene 3 partes separadas por puntos (.)

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJFbWFpbCI6ImphYWx6YUBnbWFpbC5jb20iLCJpYXQiOjE3NjMyMDgwODQsImV4cCI6MTc2MzIxMTY4NH0.5aYsIzWcCDlyfUzD31bzxzNeYvnJ6buAr1mwo5LCe3A │ │ │ │ │ └─ Firma (Signature) │ └─ Payload (Datos del usuario) └─ Header (Algoritmo y tipo)
1️⃣ Header (Encabezado):

Contiene el algoritmo de encriptación y el tipo de token

{ "alg": "HS256", // Algoritmo: HMAC SHA256 "typ": "JWT" // Tipo: JSON Web Token }
2️⃣ Payload (Carga útil):

Contiene los datos del usuario y metadatos (claims)

{ "Email": "usuario@gmail.com", // Email del usuario "iat": 1763208084, // Issued At (fecha de emisión) "exp": 1763211684 // Expiration (fecha de expiración) }
3️⃣ Signature (Firma):

Firma digital que garantiza que el token no ha sido modificado

// Se genera usando: HMACSHA256( base64UrlEncode(header) + "." + base64UrlEncode(payload), secretKey // Clave secreta del servidor )
✅ Ventajas de JWT:
  • Stateless: No requiere almacenar sesiones en el servidor
  • Portable: Se puede enviar en URL, headers o body
  • Firmado: Garantiza integridad (no puede ser modificado)
  • Con expiración: Tiene fecha de caducidad automática

3 Generación de Token JWT en el Backend

// server.js - Configuración inicial const jwt = require('jsonwebtoken'); // Clave secreta para firmar el token (guárdala en una variable de entorno) const secretKey = '';
// Endpoint para generar token después del login app.post('/generate-token/:_id', (req, res) => { const { _id } = req.params; const { email } = req.body; if (!_id) { return res.status(400).send({ error: 'Recipe ID is required' }); } // Información que deseas incluir en el token const payload = { _id, email, iat: Math.floor(Date.now() / 1000), // Fecha de emisión }; // Genera el token con expiración de 1 hora (3600 segundos) const token = jwt.sign(payload, secretKey, { expiresIn: 3600 }); // Devuelve el token generado console.log(token); res.send({ token }); });
📋 Explicación del código:
  • jwt.sign(): Crea el token JWT firmado con la clave secreta
  • payload: Datos que se incluyen en el token (email, _id, etc.)
  • expiresIn: Tiempo de expiración (3600 = 1 hora)
  • secretKey: Clave secreta que solo conoce el servidor

4 Validación de Token JWT en el Backend

// Endpoint para validar token (GET con query param) app.get('/validate-token', (req, res) => { const token = req.query.token; if (!token) { return res.status(400).send('Token is required'); } try { // Verificar y decodificar el token const decoded = jwt.verify(token, secretKey); console.log(decoded); const recipeId = decoded._id; const email = decoded.email; // Inicializa el conteo de solicitudes si no existe if (!userRequestLimit[recipeId]) { userRequestLimit[recipeId] = { count: 0, maxRequests: 10 }; } res.send({ valid: true, data: decoded, remainingRequests: userRequestLimit[recipeId].maxRequests - userRequestLimit[recipeId].count }); } catch (err) { // Token inválido, expirado o modificado res.status(401).send('Invalid token'); } });
// Endpoint protegido que requiere token (POST con token en body) app.post('/ai-assistance', (req, res) => { const token = req.body.token; if (!token) { return res.status(400).send('Token is required'); } try { // Verificar token const decoded = jwt.verify(token, secretKey); const recipeId = decoded._id; // Verificar límite de solicitudes if (userRequestLimit[recipeId].count >= userRequestLimit[recipeId].maxRequests) { return res.status(403).send('You have reached the maximum number of requests.'); } // Incrementar contador userRequestLimit[recipeId].count++; res.send({ success: true, message: 'AI assistance provided', remainingRequests: userRequestLimit[recipeId].maxRequests - userRequestLimit[recipeId].count }); } catch (err) { res.status(401).send('Invalid token'); } });
🔍 Explicación de jwt.verify():
  • Verifica la firma: Comprueba que el token no ha sido modificado
  • Verifica expiración: Rechaza tokens expirados automáticamente
  • Decodifica payload: Extrae los datos del usuario del token
  • Lanza excepción: Si el token es inválido, lanza un error

7 Flujo Completo con Validación por Token

🔑
1. Usuario hace Login con Google
Google autentica y devuelve datos del usuario
💾
2. Backend genera Token JWT
  • Backend recibe email del usuario
  • Genera token con jwt.sign()
  • Incluye email, _id, y fecha de expiración
  • Firma con clave secreta
📦
3. Frontend guarda Token
  • Token se guarda en localStorage
  • Token se incluye en URLs como query param
  • Token se puede enviar en cabecera Authorization
✅
4. Validación en Frontend
  • Verifica que existe token
  • Verifica que no esté expirado (decodifica JWT)
  • Si válido → muestra aplicación
  • Si inválido → muestra login
🌐
5. Petición API con Token
  • Frontend envía token en cabecera Authorization: Bearer <token>
  • Backend extrae token de la cabecera
  • Backend valida con jwt.verify()
  • Si válido → extrae email del token y procesa petición
  • Si inválido → devuelve error 401

8 Ventajas y Desventajas del Método con Token

✅ Ventajas:
  • Mayor seguridad: Token firmado, no puede falsificarse
  • Expiración automática: Tokens expiran sin intervención
  • Stateless: No requiere almacenar sesiones en servidor
  • Portable: Se puede enviar en URL, headers o body
  • Información incluida: Datos del usuario en el token
  • Mejor rendimiento: Menos consultas a BD
⚠️ Desventajas:
  • CORS más complejo: Requiere configurar 'Authorization'
  • Revocación difícil: No se puede invalidar fácilmente
  • Tamaño: Tokens pueden ser largos en URLs
  • Exposición: Token visible en URLs (logs, historial)
  • Configuración: Requiere manejo de secretKey seguro

9 Recomendaciones de Implementación

🔒 Seguridad:
  • Usar process.env.JWT_SECRET para la clave secreta (nunca hardcodear)
  • Usar tiempos de expiración cortos (1 hora o menos)
  • Implementar refresh tokens para renovar sin re-login
  • Validar siempre el token en cada petición
📝 Mejores Prácticas:
  • Enviar token en cabecera Authorization (no en URL si es posible)
  • Usar HTTPS siempre para proteger tokens en tránsito
  • Implementar rate limiting por token
  • Loggear intentos de tokens inválidos para seguridad
⚠️ Consideraciones CORS:
  • Asegurar que Authorization esté en allowedHeaders
  • Configurar Access-Control-Allow-Credentials: true si usas cookies
  • Probar preflight requests (OPTIONS) funcionan correctamente
  • Considerar usar query params como fallback si CORS falla

10 Resumen

📋 Para implementar validación por Token necesitas:
  1. ✅ Instalar jsonwebtoken: npm install jsonwebtoken
  2. ✅ Crear endpoint para generar tokens después del login
  3. ✅ Modificar endpoints para validar token con jwt.verify()
  4. ✅ Agregar 'Authorization' a allowedHeaders en CORS
  5. ✅ Modificar frontend para enviar token en cabecera Authorization
  6. ✅ Manejar errores de token expirado o inválido
💡 Decisión:

Validación por Email: Más simple, menos segura, funciona sin problemas CORS.
Validación por Token: Más segura, requiere configuración CORS, mejor para producción.
